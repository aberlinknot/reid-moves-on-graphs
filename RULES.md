# Правила разработки (RULES.md)

**1. Язык кода и документации**
- Весь исходный код, комментарии и docstrings — на английском языке.
- Вся пользовательская документация (README, usage, инструкции) — на русском языке.

**2. Стиль docstrings**
- Для всех функций, классов и модулей использовать стиль docstrings NumPy.

**3. Оформление коммитов и веток**
- Все сообщения коммитов и имена веток — на английском языке.
- Рекомендуется придерживаться стиля Conventional Commits (например, `feat:`, `fix:`, `docs:`, `refactor:` и т.д.).


**4. Зависимости**
- Все зависимости в requirements.txt и requirements-dev.txt должны быть зафиксированы с помощью строгих версий (==version), чтобы обеспечить воспроизводимость окружения.


**5. Аннотации типов (type hints)**
- Использовать стандартные аннотации типов Python (`typing`) во всём коде.
- Для публичных функций и классов аннотации обязательны.
- Избегать использования `Any` в основной логике; допускается только на внешних границах системы.
- Для графов использовать алиасы типов: `Node = Hashable`, `Edge = tuple[Node, Node]`.
- В docstring'ах типов отражать именно алиасы, а не сырые типы.

**6. Форматирование и стиль кода**
- Максимальная длина строки: 100 символов (enforced by black, isort, flake8).
- Форматирование: black (одинарные кавычки, кроме docstring'ов).
- Порядок импортов: isort с профилем black.
- Линтер: flake8 (игнорировать E203, W503).

**7. Прочее**
- Соблюдать структуру проекта (см. README) и поддерживать чистоту репозитория.
- Перед слиянием изменений — проверять, что проект собирается и тесты проходят.
